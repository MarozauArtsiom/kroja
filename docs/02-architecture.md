# 02 — Архитектура

## Стек

| Слой | Что | Зачем именно это |
|---|---|---|
| Фреймворк | Next.js 15, App Router | Статическая генерация лендинга, клиентский конструктор, один деплой |
| Язык | TypeScript strict, без `any` | Матрица опций и ключи словаря проверяются компилятором, а не в рантайме |
| Стили | Tailwind CSS, токены в `tailwind.config.ts` | Своя эстетика бренда без UI-кита |
| Валидация | Zod | Одна схема разбирает ссылку, localStorage и тело запроса к API |
| Корзина | Zustand + `persist` в localStorage | Минимальный стор, переживает перезагрузку |
| Деплой | Vercel | Без настройки, preview на каждый push |

Зависимостей ровно шесть: `next`, `react`, `react-dom`, `zod`, `zustand`, `clsx`. Новые пакеты не добавляются без явного решения — см. `AGENT.md`.

Бэкенда, базы данных, CMS и авторизации **нет**. Единственная серверная ручка — `/api/reserve`.

## Слои

```
types/            Типы предметной области: Configuration, коды осей, Dictionary
   ▲
content/          Данные о продукте: размеры, кожи, цвета, цены, карманы, наличие
   ▲              + словари шести языков (content/i18n)
lib/              Чистые функции: цена, правила совместимости, карманы, ссылка, форматирование
   ▲              Никакого React, никакой локали
components/       React. Читают данные через lib/data.ts, тексты через useI18n()
   ▲
app/              Маршруты Next.js: страницы, метаданные, API, sitemap/robots
```

Правила слоёв:

- **`lib/` не знает про язык.** Если функции нужно сообщить о событии (например, «карманы урезаны»), она возвращает код события, а фразу собирает компонент со словарём. Пример — `ConfigChange` в `lib/availability.ts` и `components/configurator/change-message.ts`.
- **Компоненты берут данные через фасад `lib/data.ts`**, а не напрямую из `content/*`. При переезде на CMS меняется один файл. `lib/*` может читать `content/*` напрямую.
- **Деньги — целые гроши** (`30000` = 300 zł), суффикс `Minor`. Никакой плавающей точки.
- **Меры — миллиметры и граммы**, суффиксы `Mm` и `G`.
- **Импорты абсолютные** через `@/`.

## Поток данных конструктора

Источник истины конфигурации — **адресная строка**. Ни в каком React-состоянии конфигурация не хранится.

```
URL ?size=a5&leather=croc&pk=d,c+|m&...
  │
  ▼  configFromSearchParams()         lib/config-url.ts
сырой объект
  │
  ▼  parseConfig()                    lib/config-schema.ts   (Zod; мусор → значения по умолчанию)
Configuration (типы верны)
  │
  ▼  resolveConfiguration()           lib/availability.ts    (правила; невозможное → ближайшее возможное)
Configuration (валидна) + ConfigChange[]
  │
  ├─▶ calculatePrice()                lib/pricing.ts         → цена
  ├─▶ SchematicCover                  components/schematic   → чертёж
  └─▶ селекторы                       components/configurator → интерфейс
```

Изменение идёт обратным путём. Селектор вызывает `update(patch)` из хука `useConfigurator`:

1. патч накладывается на текущую конфигурацию;
2. `resolveConfiguration` приводит результат к допустимому и возвращает список изменений;
3. каждое изменение показывается тостом на языке страницы;
4. `configToSearchParams` пишет конфигурацию в ссылку (только отличия от умолчания);
5. Next перерисовывает страницу из новой ссылки.

Смена размера и кожи пишет запись в историю браузера (`router.push`), остальное — заменяет текущую (`router.replace`). Кнопка «назад» откатывает крупные решения, а не каждое нажатие «+».

Отсюда свойства, которые не нужно отдельно поддерживать:

- любой экран конструктора — это ссылка, ею можно поделиться;
- «изменить» в корзине — просто ссылка на конструктор с конфигурацией позиции;
- битая или устаревшая ссылка не роняет страницу — на каждом шаге есть значение по умолчанию.

Дополнительно конструктор сохраняет последнюю конфигурацию в `localStorage` (`nakedskin:last-config`) и при пустой ссылке предлагает её восстановить.

## Маршрутизация и языки

```
/                      → middleware: cookie NEXT_LOCALE или Accept-Language → /{lang}
/configurator          → то же
/{lang}                → лендинг
/{lang}/configurator   → конструктор
/{lang}/shotlist       → список кадров (noindex)
/{lang}/что-угодно     → локализованная 404 (app/[lang]/not-found.tsx)
/api/reserve           → POST: резерв и «сообщить о наличии»
```

Языки: `en`, `pl`, `de`, `by`, `uk`, `ru`. Все страницы `/{lang}/…` генерируются статически для каждого языка (`generateStaticParams`). Подробно — [04-i18n.md](04-i18n.md).

## Корзина

Позиция корзины — полная конфигурация с посчитанной ценой и сроком. Две одинаковые конфигурации складываются в одну позицию с количеством 2. «Одинаковость» определяет `configHash`: строка из всех осей, где вкладыши отсортированы (порядок типов не важен), а карманы — в исходном порядке (одни и те же карманы в другом порядке — другое изделие).

Корзина живёт в localStorage под ключом `nakedskin:cart` с версией 3. При несовместимом изменении модели версия поднимается, а `migrate` сбрасывает корзину: старые конфигурации нельзя честно перевести в новые оси, а молча показать искажённую позицию хуже, чем пустая корзина.

## API `/api/reserve`

`POST`, тело — одно из двух:

| `kind` | Поля | Когда |
|---|---|---|
| `reservation` | `email`, `cart[]` (конфигурация + количество), `cartTotalMinor`, `ts` | Кнопка резерва в корзине |
| `stock-notify` | `email`, `leather`, `color` | «Сообщить о наличии» у недоступного цвета |

Тело проверяется Zod-схемой (конфигурация — той же `configSchema`, что и ссылка). Данные всегда пишутся в лог сервера; если заданы `RESEND_API_KEY` и `RESERVE_NOTIFY_EMAIL`, дополнительно уходит письмо владельцу. Ошибка почты не роняет запрос пользователя.

## Производительность

- Лендинг и все локализованные страницы — статические, отдаются с CDN.
- Конструктор — клиентский компонент внутри `Suspense`; лендинг не тянет его код.
- Изображений нет: превью — inline SVG, сетевых запросов за картинками ноль.
- Первая загрузка ~170 kB JS на страницу (общие 103 kB).
