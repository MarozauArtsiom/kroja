# 05 — Эксплуатация и типовые правки

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Разработка на `localhost:3000` |
| `npm run build` | Продакшен-сборка; генерирует все страницы для пяти языков |
| `npm run start` | Запуск собранного |
| `npm run lint` | ESLint **и** проверка переводов (`npm run i18n`) |
| `npm run i18n` | Только детектор пропущенных переводов |
| `npm run shotlist` | Пересобирает `shotlist.md` в корне из текущих данных (на английском) |

Перед каждым коммитом:

```bash
npx tsc --noEmit && npm run lint && npm run build
```

⚠️ `npm run build` перезаписывает `.next/`. Если в том же каталоге запущен `npm run dev`, его после сборки нужно перезапустить.

## Переменные окружения

| Переменная | Нужна для | Без неё |
|---|---|---|
| `RESEND_API_KEY` | Отправка письма о резерве владельцу через Resend | Резервы только в логе сервера |
| `RESERVE_NOTIFY_EMAIL` | Адрес, куда слать письма о резервах | То же |

Шаблон — `.env.example`. Локальные значения — `.env.local` (в git не попадает).

## Деплой

Vercel, сборка из git. Отдельной настройки не требуется. Домен в метаданных, `sitemap.xml` и `robots.txt` — `nakedskin.vercel.app`.

## Работа агентов

Проект ведут несколько кодинг-агентов. Их правила — в `AGENT.md`, ход работ — в `STATUS.md`. Коротко: задачи по порядку, один коммит на задачу, сборка зелёная после каждой, любое отклонение от постановки записывается в раздел «Расхождения».

## Рецепты

Большинство продуктовых правок — **правка данных**, а не кода. Если для изменения цены или ассортимента понадобилось лезть в компонент — что-то сделано не так.

### Изменить цену

| Что | Где |
|---|---|
| База размера | `content/sizes.ts › basePriceMinor` |
| Надбавка за кожу | `content/leathers.ts › priceDeltaMinor` |
| Пряжка, петля, тиснение, коробка | `content/pricing.ts` — константы `*_MINOR` |
| Цена вкладыша | `content/pricing.ts › insertPriceMinor` |
| Сколько вкладышей бесплатно | `content/pricing.ts › INCLUDED_INSERTS` |
| Надбавка за цвет нити | `content/threads.ts › priceMinor` у нужного цвета |

Суммы — в грошах: `2500` = 25 zł.

### Ограничить ассортимент кожи

Сейчас всё доступно везде. Когда мастер скажет реальные остатки:

- **кожа не бывает в этом цвете** — убрать цвет из `availableColors` в `content/leathers.ts`;
- **кожа не кроится в этом размере** — убрать размер из `availableSizes`;
- **цвет временно кончился или только под заказ** — в `content/availability.ts` поставить паре `'unavailable'` или `'made_to_order'`.

Конструктор подхватит сам: недоступные свотчи станут серыми, под заказ — с подписью и сроком 14 дней, ссылки со старыми комбинациями подменят цвет с тостом. У цвета, который в этой коже бывает, но кончился (`'unavailable'`), по клику откроется «сообщить о наличии»; цвет, которого в коже нет вовсе, просто неактивен. Список кадров перестанет включать недоступные пары.

### Поменять высоты карманов или нахлёст

`content/pockets.ts`: `heightMm` у типа, `POCKET_OVERLAP_MM`, `MAX_POCKETS_PER_FLAP`, `FLAP_MARGIN_MM`. Бюджет, проверки, кнопки, чертёж и починка старых ссылок пересчитаются сами.

### Добавить тип кармана

1. `types/config.ts › PocketKind` — новый код.
2. `content/pockets.ts` — запись с высотой, буквой для ссылки (уникальной!), `canDivide`.
3. `lib/config-schema.ts › pocketSchema` — код в `z.enum`.
4. Пять словарей, `options.pockets` — название и «что кладут». Компилятор покажет все пять мест.
5. Если форма не прямоугольная — ветка в `PocketStack` в `components/schematic/views/OpenView.tsx`, как у уголка.

### Добавить цвет кожи

1. `types/config.ts › ColorCode`.
2. `content/colors.ts` — hex и порядок подстановки.
3. `lib/config-schema.ts` — код в `z.enum` цвета.
4. `content/availability.ts` — пары с каждой кожей, которая есть в этом цвете.
5. `availableColors` у нужных кож в `content/leathers.ts`.
6. Пять словарей, `colors`.

### Переместить дырки в корешке

`SPINE` в `components/schematic/schematic-parts.tsx`: координаты для вида спереди. Вид сзади зеркалит их сам.

### Изменить диаметры петли

`content/pen-holders.ts › minMm / maxMm`. Подписи на карточках, выноски на чертеже и круги-линейка берут числа отсюда — дублей нет.

### Показать или скрыть секцию лендинга

`content/sections.ts`: `patina`, `reviews` — включать только когда есть настоящий кадр или настоящие отзывы; `process` — `'full'`, `'compact'` или `false`.

### Перейти на фотографии

Когда съёмка состоится:

1. Файлы — в `public/previews/` с именами из `shotlist.md` (`{кожа}_{цвет}_{ракурс}.webp`).
2. `lib/assets.ts › ASSET_MODE = 'photo'`.
3. В `Preview.tsx` передать в `getPreview` локализованный alt (третий параметр).

Ракурс `back` остаётся чертежом всегда — его не фотографируют, `getPreview` это знает. Размер в имени файла не участвует: одна фотография на все четыре размера, масштаб показывает схема габаритов.

### Поднять версию корзины

Если модель конфигурации изменилась несовместимо — в `store/cart.ts` увеличить `version` в настройках `persist`. Старые корзины сбросятся через `migrate`. Ключ последней конфигурации в `RestoreBanner.tsx` при этом можно не трогать: она проходит через `parseConfig` и сама становится валидной.
