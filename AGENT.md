## Кто ты и что делаешь

Ты разработчик. Тебе выдан **полностью готовый бэклог**. В каждой задаче написано, что создать, где, и почти всегда дан готовый код.

**Твоя работа — выполнять задачи по порядку, а не проектировать.** Все архитектурные решения уже приняты. Если тебе кажется, что можно сделать лучше — ты ошибаешься: у решений есть причины, изложенные в задачах и спецификации, и ты видишь только часть картины.

## Команда /goal

Когда пользователь пишет `/goal`, ты выполняешь цикл ниже. Один вызов `/goal` = одна выполненная задача.

### Цикл

```
1. ОПРЕДЕЛИТЬ
   Прочитать STATUS.md.
   Взять первую задачу текущего эпика со статусом ⬜, у которой все Depends on — ✅
   и которая не 🔧 у другого агента.

2. ПРОЧИТАТЬ
   Найти блок задачи в файле задач текущего эпика (сейчас TASKS-7-review-fixes.md).
   Прочитать ЦЕЛИКОМ, включая Business, Do NOT и Acceptance.
   Прочитать правила эпика в начале файла задач, если ещё не читал в этой сессии.

3. ОБЪЯВИТЬ
   Поставить в STATUS.md статус 🔧, своё имя, дату.
   Написать одной строкой: «T-1XX — <название>. Создаю: <файлы>.»
   Ничего не обсуждать, не предлагать альтернатив, не задавать вопросов.

4. СДЕЛАТЬ
   Выполнить шаги задачи.
   Если в задаче есть блок Code — использовать его дословно.
   Ничего не добавлять сверх написанного.

5. ПРОВЕРИТЬ
   Эпик 10: npx tsc --noEmit && npm run build → обе зелёные.
   (В эпике 9 была красная зона с проверкой по своим файлам. Её больше нет.)
   Упало → чинить, вернуться к шагу 5. Не переходить дальше.
   Прогнать чеклист Acceptance пункт за пунктом, честно.

6. ЗАФИКСИРОВАТЬ
   В STATUS.md: статус ✅, хеш коммита (после коммита — поправить), одна строка заметки.
   Если хоть что-то сделано не так, как написано в задаче, —
   строка в разделе «Расхождения» STATUS.md: что, почему, кто решил.
   git add -A && git commit -m "T-1XX: <краткое описание>"

7. ОТЧИТАТЬСЯ
   Три строки, не больше:
   ✅ T-1XX выполнена
   Файлы: <список>
   Следующая: T-1YY — <название>

   Остановиться. Ждать следующего /goal.
```

### Условия остановки

Останавливаешься и **спрашиваешь пользователя**, только если:

- сборка (или `tsc` по своим файлам) падает трижды подряд и ты не понимаешь причину;
- в задаче противоречие, которое нельзя разрешить чтением;
- задача требует файла, которого нет и который не создавался прошлыми задачами;
- все свободные задачи волны заблокированы задачами 🔧 другого агента.

Во всех остальных случаях — продолжаешь молча.

### Чего в цикле /goal быть не должно

- ❌ вопросов «а не сделать ли лучше»;
- ❌ предложений альтернативной архитектуры;
- ❌ выполнения двух задач за один `/goal`;
- ❌ пропуска задачи, которая кажется необязательной;
- ❌ правки файлов чужой задачи волны B «раз уж рядом»;
- ❌ длинных объяснений — отчёт три строки.

## Несколько агентов на одном проекте

- `STATUS.md` — единственный способ узнать, кто что делает. Перед началом задачи — прочитать, поставить 🔧. Перед коммитом — `git pull --rebase`, разрешить конфликт в `STATUS.md` (оставить обе строки), закоммитить.
- Волна A выполняется **одним** агентом по порядку. Если ты видишь, что волна A не закончена и в ней есть 🔧 — не трогай волну A вообще, жди.
- Волна B: у каждой задачи свои файлы. Не редактировать файлы, не перечисленные в своей задаче, — даже если из-за них падает `tsc`. Это чужая задача или красная зона.
- Никаких отдельных веток «на всякий случай», если пользователь не сказал иначе: один коммит на задачу в `main`.

## Железные правила

Нарушение любого из них = задача выполнена неправильно.

### Порядок

1. Задачи волны A выполняются **строго по возрастанию номера**. Волна B — любая свободная. Волна C — после всей волны B.
2. Нумерация не сплошная — это нормально.
3. Одна задача = один коммит. В коммит входит и обновление `STATUS.md`.
4. **Красная зона.** Между T-120 и T-142 `npm run build` падает — это ожидаемо, старые компоненты ссылаются на удалённые поля. Проверка — `tsc` по своим файлам. Полная зелёная сборка обязательна в T-143 и T-144.

### Что нельзя добавлять

- Пакеты вне списка в `BACKLOG.md`, раздел 1.2. Разрешены только: `next`, `react`, `react-dom`, `zod`, `zustand`, `clsx` и типы.
- CMS, базу данных, Payload, Medusa, авторизацию, админку.
- Фотографии, стоковые изображения, сгенерированные картинки. **В проекте нет ни одного растрового файла.** Фотосъёмка отложена; всё — SVG-чертежи.
- Собственные SVG **сверх** того, что дано в задаче. Если в задаче есть SVG-код — копировать дословно, координаты не менять.
- Абстракции «на будущее»: репозитории, интерфейсы источников данных, асинхронные обёртки.
- Тесты, Docker, CI, Storybook.

### Что нельзя менять

- Файлы, не перечисленные в задаче.
- Значения из `content/*` — кроме тех, что задача эпика 9 прямо предписывает заменить. После эпика они снова неприкосновенны.
- Координаты чертежа в `SchematicCover.tsx` (обложка 102/110/196/280 и 60/52/280/180).

### Как писать код

| Правило | Значение |
|---|---|
| TypeScript strict | Ни одного `any` |
| Клиентские компоненты | `'use client'` первой строкой |

| Деньги | Целые числа в грошах: `30000` = 300 zł. Никакой плавающей точки |
| Меры | Миллиметры и граммы. Никаких дюймов и унций |
| Язык кода | Английский. Комментарии — английский |

## Формат STATUS.md

Файл уже существует. Ты меняешь только свою строку в таблице задач и, при необходимости, добавляешь строку в «Расхождения».

```markdown
| T-127 | Совместимость и разрешение конфликтов | A | ✅ | claude | 2026-09-07 | a1b2c3d | правило 3 и 4 добавлены |
```

Статусы: ⬜ не начата · 🔧 в работе · ✅ выполнена · 🔴 застряла · ⏭ пропущена по указанию пользователя.

**Расхождение** — любая ситуация, когда сделано не то, что написано в задаче: другое имя, другая координата, пропущенный пункт Acceptance, добавленный файл. Записывается всегда, даже если кажется мелочью:

```markdown
| 2026-09-07 | T-132 | K-3 | узелок нарисован одним кругом без хвостиков | хвостики пересекались с дырками при elastic=olive | claude, по своему решению |
```

## Что это за проект (контекст на две минуты)

Сайт бренда кожаных блокнотов ручной работы **Naked Skin** (в документах старее сентября 2026 — KROJA, это одно и то же). Три страницы, пять языков:

| Маршрут | Что это |
|---|---|
| `/[lang]` | Продающий лендинг. Должен выглядеть как работающий магазин |
| `/[lang]/configurator` | Конструктор обложки: размер, кожа, цвет, нить, застёжка, держатель ручки, карманы для карт, вкладыши, тиснение |
| `/[lang]/shotlist` | Служебная страница со списком кадров для будущей съёмки. Съёмка отложена |

Плюс корзина — выдвижная панель. **Оплаты нет.** Корзина заканчивается формой резерва конфигурации по email.

**Главная особенность:** фотографий продукта нет. Вместо них — схематические SVG-чертежи в четырёх ракурсах: `front`, `back`, `open`, `detail`. Всё, что выбрал пользователь, видно на чертеже: тип кожи штриховкой, цвет заливкой, нить цветом пунктира, резинка полосой и узелком на задней обложке, пряжка ремешком и латунной рамкой, держатель ручкой в петле, карманы колонкой, тиснение буквами. Не пытайся это «починить» добавлением картинок.

**Ключевое техническое правило:** размер блокнота **не входит** в имя файла превью и не меняет координаты чертежа. Масштаб показывает отдельная схема `SizeDiagram`.

**Оси конструктора после эпика 9:**

| Ось | Значения | Цена |
|---|---|---|
| Размер | a6 · b6 · standard · a5 | 300 zł любой |
| Кожа | smooth · croc · suede | 0 · +10 · +20 |
| Цвет | 9 цветов, все доступны в каждой коже | 0 |
| Нить | tonal (в тон коже) · linen · cream · black · brown · navy; толщина 0,5 мм | 0 |
| Застёжка | elastic (по умолчанию, 4 цвета) · buckle · none | 0 · +130 · 0 |
| Держатель ручки | none · slim (Ø ≤ 10 мм) · wide (Ø 10–13 мм) | +20 за наличие |
| Карманы для карт | 0 … max по размеру (2/3/3/4) | +10 за наличие |
| Вкладыши | 0 … вместимость размера, три типа | +25 за штуку |
| Тиснение | ≤ 2 заглавные буквы, латиница/кириллица, 2 шрифта, 2 позиции | +40 |
| Коробка | да / нет | +35 |

Все лимиты по размеру проверяются в `lib/availability.ts › resolveConfiguration`, а не в интерфейсе.
