# 09 — План работ

**Срок: 11–14 рабочих дней** (без корзины — 11, с корзиной — 14)

**Внешняя зависимость:** 6 пилотных фотографий от мастера и решение по ценам. Без них лендинг не закрывается — см. блокеры в `01-mvp-scope.md`.

---

## Что изменилось в v0.4

MVP адресован одному человеку — мастеру, и служит объяснением состава съёмки. Это убрало из критического пути сразу три вещи:

| Ушло | Почему |
|---|---|
| Финальный копирайт *(частично вернулся в v0.6 — для лендинга)* | Для конструктора и служебных текстов черновика достаточно |
| Аналитика | Зритель один |
| Email-захват | Служил тесту спроса, которого нет |
| Коридорные тесты с пятью посторонними | Проверка одна: понял ли мастер |

Добавилась одна вещь: страница `/shotlist` — главный артефакт.

**Критических путей теперь два:**
1. **Визуальный язык схем** — пока не решено, как выглядит чертёж обложки с выносками, конструктор писать бессмысленно
2. **Пилотные фото и цены** — блокируют закрытие лендинга, но не его вёрстку. Запрашивать у мастера в первый же день, параллельно разработке

### Что добавилось в v0.6

Лендинг поднят до production-ready: финальный копирайт, настоящие фото и цены, Lighthouse ≥ 95, полный WCAG AA, возврат email-захвата как резерва конфигурации. Это +3 дня и отдельный спринт отделки.

## Спринты

### Спринт 0 — Визуальный язык (1–2 дня)

| Задача | Результат |
|---|---|
| **Дизайн-система на финальном уровне** | Типографика, палитра, токены. Мок должен впечатлять мастера, поэтому эстетика — не «потом» |
| **Схема обложки в трёх ракурсах** | Чертёж в эстетике бренда: контур, штриховка, шов, выноски, рамка кадра, плашка «NOT IN FRAME», имя файла |
| Три паттерна штриховки кож | `diagonal-fine`, `diagonal-coarse`, `cross-hatch` |
| Раскладка `/shotlist` | Экран + версия для печати A4 |
| Раскладка конструктора | Десктоп + мобайл, состояния конфликтов |
| Финальный список комбинаций | Сколько кож и цветов — определяет объём съёмки, обсудить с мастером **до** разработки |
| **Запрос пакета 0 у мастера** | 6 пилотных фото — отправить требования в первый день, чтобы снимал параллельно разработке |
| **Расчёт юнит-экономики** | Настоящие цены вместо плейсхолдеров |
| Тексты требований к съёмке | Точные формулировки выносок и правил |
| **Финальный копирайт лендинга** | Не черновик: страница должна выглядеть покупаемой |
| Черновик остальных текстов | С пометкой `// DRAFT` |

**DoD:** видно, как выглядит одна схема со всеми выносками. Дальше это тиражируется кодом.

⚠️ Список комбинаций согласовать с мастером в этом спринте. Если у него готовы изделия только в двух кожах, вся матрица меняется, и лучше узнать это до, а не после.

### Спринт 1 — Конструктор и схемы (5–6 дней) ⭐

| Задача |
|---|
| Инициализация Next.js, TypeScript, Tailwind, токены |
| `/content`: sizes, leathers, colors, availability, shots, sections |
| `lib/config-schema.ts` — Zod-схема |
| `lib/config-url.ts` — URL-состояние, граничные случаи |
| `lib/availability.ts` — матрица совместимости, разрешение конфликтов |
| `lib/pricing.ts` — расчёт цены |
| `lib/assets.ts` — резолвер `ASSET_MODE` |
| **`SchematicCover.tsx` — SVG-чертёж: контур по размеру, штриховка по коже, чип цвета, пунктир шва по нити, зона гравировки, страницы по вкладышам** |
| **Три ракурса с выносками, рамкой кадра, плашкой «NOT IN FRAME», именем файла** |
| Раскладка: sticky-превью, колонка опций, sticky-панель |
| Селекторы: размер, кожа, цвет, нить, шнур |
| SVG-схема габаритов + подпись «размер снимать не надо» |
| Гравировка: поле, валидация, подсветка зоны |
| Опции: вкладыши, коробка |
| Конфликты: тосты, баннеры, недоступные свотчи |

**DoD:** любая валидная комбинация даёт корректную схему; имя файла под схемой соответствует ключу; смена размера имя файла не меняет.

**DoD:** `/shotlist` печатается на A4 без потери информации; общее число кадров выведено однозначно; сюжетные слоты попали в список.

### Спринт 3 — Доведение лендинга (2–3 дня)

Отдельный спринт, потому что production-ready — это не «дописать пару стилей».

| Задача |
|---|
| Адаптив доведён: 360 px, планшет, десктоп, широкий экран |
| Полный аудит WCAG 2.1 AA: клавиатура, скринридер, контраст на фото |
| Lighthouse ≥ 95 по всем четырём осям |
| 404, favicon, OG-превью, метатеги, JSON-LD |
| Состояния hover/focus, скролл-анимации, микровзаимодействия |
| Вычитка финального копирайта |
| Проверка: ни одной плашки-заглушки в основном потоке |

**DoD:** страница не отличима от работающего магазина, у которого просто пока закрыт приём заказов.

### Спринт 4 — Корзина (2–3 дня) — **опционально**

Не служит цели MVP. Делать, только если хочешь, чтобы прототип был готов к следующей стадии без доработок.

| Задача |

Если резать срок — режется первым, целиком, без последствий для остального.

## Приоритеты

| Приоритет | Что | Комментарий |
|---|---|---|
| P0 | Схема обложки с выносками и именем файла | Без этого MVP не существует |
| P0 | `/shotlist` с печатью | Главный артефакт |
| P0 | Конструктор: размер, кожа, цвет, матрица доступности | Показывает, откуда берётся число кадров |
| P0 | Лендинг production-ready: 6 фото, финальный текст, цены | Главный источник мотивации |
| P0 | Резерв конфигурации вместо тупика в корзине | Иначе лендинг противоречит сам себе |

| P1 | Слоты на лендинге с описанием сюжетов | Сюжетные кадры иначе не объяснить |
| P1 | Секция S6 «Процесс» | Единственные кадры, которые нельзя доснять потом |

## После MVP

**Шаг 1 — сессия с мастером.** Порядок важен: сначала лендинг и конструктор (впечатление), затем `/shotlist` и бриф `14-master-brief.md` (задача). Пакет 1 брифа — вопросы об ассортименте и коже — можно пройти прямо на этой встрече. Записать все вопросы мастера о съёмке: каждый — место, где спецификация написана непонятно.

**Шаг 2 — согласовать объём.** Возможно, 36 продуктовых кадров окажется много для первой итерации. Варианты сокращения (две кожи вместо трёх, отказ от ракурса `detail`) описаны в `12-schematic-assets.md`, раздел 9.

**Шаг 3 — съёмка.**

**Шаг 4 — подстановка фото:** 1–2 дня, процедура в `12-schematic-assets.md`, раздел 8. Ни один компонент конструктора не переписывается.

**Шаг 5** — дальнейшие фазы (копирайт, аналитика, email-захват, продажи) — по порядку из `13-next-phases.md`.
