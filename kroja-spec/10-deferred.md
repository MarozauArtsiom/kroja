## Фаза 1.5 — Фотосъёмка

Вынесена из MVP. Технически это не «фаза 2»: она не требует чекаута и не открывает продажи, но именно она превращает прототип в инструмент публичного теста спроса.

| Что | Объём |
|---|---|
| Превью конструктора | ~45 кадров, ключ `{leather}_{color}_{angle}`, без шнура и гравировки в кадре |
| Лендинг | ~11 сюжетных кадров, список генерируется скриптом из `<PhotoSlot>` |
| Подстановка в код | 2–3 дня, ни один компонент конструктора не переписывается |
| Что разблокируется | Публичный запуск, аналитика, email-захват, секция S8 |

Полная спецификация, список кадров и процедура замены — в `12-schematic-assets.md`.

**Предпосылка:** нужны готовые изделия хотя бы в части цветов. Если их нет, снимать нечего, и съёмка откладывается независимо от готовности кода. Это единственная зависимость проекта от физического производства — и главная причина согласовать объём матрицы с мастером до начала разработки.

## Фаза 2 — Открытие продаж

Это минимум, необходимый, чтобы принять первый реальный заказ.

### 2.1 Чекаут и оплата

| Компонент | Решение |
|---|---|
| Форма чекаута | Одностраничная, гостевая, без регистрации |
| Провайдер | **Stripe** — поддерживает BLIK и Przelewy24, что критично для Польши |
| Способы оплаты | BLIK, Przelewy24, карты, Apple Pay, Google Pay |
| Альтернативы Stripe | Przelewy24 напрямую, Tpay, PayU — дешевле по комиссии, но хуже DX и слабее для ЕС |

**BLIK обязателен.** Это доминирующий способ оплаты в Польше, его отсутствие отсекает значимую долю польских покупателей.

### 2.2 Доставка

| Направление | Решение |
|---|---|
| Польша | InPost Paczkomat (виджет выбора точки) + InPost курьер |
| ЕС | DPD / DHL по зонам, ставки таблицей |
| Расчёт | В корзине, до чекаута — не в конце |
| Порог бесплатной доставки | Определить после расчёта юнит-экономики |

### 2.3 Хранение заказов

Минимальная схема: заказ создаётся после успешной оплаты, хранится в лёгкой БД (SQLite/Postgres на Vercel) либо, на малых объёмах, просто в Airtable через API. Полноценная админка не нужна, пока заказов меньше 50 в месяц.

### 2.4 Транзакционные письма

Четыре шаблона:
1. Подтверждение заказа — сразу, с полной конфигурацией и превью
2. «Взяли в работу» + **фото изделия в процессе** — день 2–3
3. Отправлено + трек-номер
4. Запрос отзыва + промо на вкладыши — день 30

Второе письмо — самое недооценённое. Оно превращает срок ожидания из тревоги в часть продукта.

### 2.5 Юридический пакет

Обязателен к моменту первой продажи. Полный список — в `11-legal-and-open-questions.md`.

## Фаза 3 — Рост

### 3.1 Страницы, отделяемые от лендинга

| Страница | Когда отделять | Зачем |
|---|---|---|
| `/leather` | Когда контента станет больше одного экрана | SEO по запросам о типах кожи |
| `/craft` | Вместе с /leather | Глубина доверия, база для контент-маркетинга |
| `/collection` + `/product/*` | При 6+ моделях | Лендинг перестанет вмещать выбор |
| `/refills` | Сразу после открытия продаж | Единственный источник повторных покупок |
| `/accessories` | Тогда же | Средний чек |
| `/care` | Позже | Пока живёт аккордеоном |
| `/corporate` | Как только появится первый B2B-запрос | Канал с самым коротким путём к обороту |
| `/faq` | При 12+ вопросах | |

### 3.2 Локализация

Порядок: **EN (MVP) → PL → DE**.

Польский добавляется, когда тексты устоятся. Немецкий — когда данные покажут долю трафика из DACH: это самый платёжеспособный рынок для ремесленных кожаных товаров в ЕС.

Технически: архитектура MVP уже готова (все строки в `copy.ts`), нужен только роутинг `/[locale]/`, `hreflang` и словари.

### 3.3 Мультивалютность

PLN + EUR, определение по стране доставки с возможностью ручного переключения. Не раньше, чем появится реальный трафик из-за пределов Польши.

### 3.4 Функциональность

| Что | Приоритет | Комментарий |
|---|---|---|
| Отзывы с фото и модерацией | Высокий | Главный фактор доверия в handmade |
| Аккаунты и история заказов | Низкий | При покупке раз в несколько лет не окупает сложности |
| Wishlist | Низкий | Shareable URL конфигурации уже закрывает эту потребность |
| Подписка на вкладыши | Средний | Реальный LTV-механизм, требует налаженного производства |
| Динамическое OG-изображение конфигурации | Средний | Расшаренная ссылка показывает собранный блокнот — сильный виральный эффект |
| Пресеты конфигураций («Classic», «Traveller») | Средний | Лечит паралич выбора, если метрики покажут перебор |
| Подарочные сертификаты | Средний | Решает проблему «дарю, но не знаю его вкус» |
| Складской учёт | Средний | Когда ручной правки JSON станет мало |
| 3D или видео-превью | Низкий | Только если фотоматрица упрётся в потолок |

## Альтернативы Shopify — если понадобится платформа

Решение MVP — не использовать платформу вообще (см. `02-tech-stack.md`). Когда объём заказов вырастет, варианты в порядке применимости к этому проекту:

| Платформа | Тип | Плюсы | Минусы | Кому подходит |
|---|---|---|---|---|
| **Оставить Next.js + Stripe** | своё | Полный контроль конструктора, нет абонплаты, нет потолка вариантов | Заказы, письма, склад пишутся руками | **Рекомендуется** при < 100 заказов/мес |
| **Medusa.js** | headless, open source, Node | Заказы, склад, промо, регионы из коробки; фронт остаётся своим на Next.js; та же экосистема | Нужен хостинг и БД, требует бэкенд-компетенции | Оптимально при росте объёмов |
| **Saleor** | headless, open source, Python/GraphQL | Зрелый, сильный GraphQL API, мультиканальность | Тяжелее в поддержке, другой стек | Если появится команда |
| **Vendure** | headless, open source, Node/TS | Отличная типизация, плагинная архитектура | Меньше сообщество | Альтернатива Medusa |
| **Snipcart** | скрипт поверх своего сайта | Подключается к готовому Next.js за день, кастомные поля товара | 2% с оборота сверх комиссии эквайринга | Быстрый способ включить оплату без переезда |
| **Swell** | headless SaaS | Гибкие атрибуты товара, хорош для кастомизации | Платный, vendor lock-in | Компромисс между своим и SaaS |
| **Shoper / IdoSell** | польские SaaS | Локальные платежи и логистика из коробки, польская поддержка | Тесная вёрстка, конструктор не встроить нормально | Не подходит из-за конструктора |
| **WooCommerce** | WordPress | Дёшево, много готового | PHP, производительность, безопасность требуют внимания | Не подходит стеку |

**Практический вывод:** переезд на платформу нужен не ради оплаты (Stripe решает это в чистом Next.js), а ради админки — чтобы менять наличие, цены и тексты без правки файлов и деплоя.

⚠️ **Подробный разбор двух основных кандидатов — в `15-platform-comparison.md`.** Таблица выше остаётся как обзор ландшафта.

## Маркетинг и каналы (за пределами разработки)

Зафиксировано, чтобы не потерялось при планировании после MVP:

1. **Instagram и TikTok** — timelapse патинирования, ASMR седельного шва, распаковка. Категория виральна.
2. **Pinterest** — недооценённый канал для journaling и stationery, длинный хвост трафика.
3. **Etsy** — параллельная витрина, решает проблему холодного доверия к новому бренду.
4. **B2B корпоративные подарки** — сотни IT-компаний и SSC в Кракове, самый короткий путь к обороту.
5. **Крафт-маркеты в Кракове** — единственный способ дать людям потрогать продукт, плюс живая обратная связь по конструктору.
6. **Микроинфлюенсеры в planner-сообществах** DACH и Бенилюкса — аудитория, уже покупающая Gillio и Van der Spek.
