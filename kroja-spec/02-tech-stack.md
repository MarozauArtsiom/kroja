# 02 — Технический стек

## Решение

**Next.js 15 (App Router) + TypeScript + Tailwind. Без коммерческой платформы, без CMS, без базы данных.**

## Почему не Shopify и не другая платформа

Коммерческая платформа решает задачи, которых в MVP нет: приём платежей, хранение заказов, учёт склада, налоги, доставка. Ни одна из них не входит в скоуп. Взамен платформа привносит то, что мешает главному:

- Конструктор упирается в модель вариантов товара (у Shopify — потолок и жёсткая структура опций), кастомная логика совместимости пишется поверх чужих ограничений
- Тема навязывает вёрстку и разметку, кастомная секция конструктора живёт в чужом окружении
- Абонплата и комиссии за то, что не используется
- Замедляется главный цикл: правка конструктора требует деплоя темы, а не `npm run dev`

Для двух страниц без оплаты платформа — чистый оверхед. Когда дойдёт до реальных продаж, варианты рассмотрены в `10-deferred.md`.

## Состав

| Слой | Решение | Обоснование |
|---|---|---|
| Фреймворк | Next.js 15, App Router | SSG для лендинга, клиентский конструктор, готовый `next/image` |
| Язык | TypeScript, strict | Матрица совместимости кожа×цвет должна проверяться типами, а не в рантайме |
| Стили | Tailwind CSS + CSS-переменные для токенов | Быстро, токены дают дизайн-систему без отдельной библиотеки |
| Состояние конструктора | URL (`useSearchParams`) как источник истины + `useReducer` | URL уже обязателен для шаринга — не заводим второй источник истины |
| Состояние корзины | Zustand + persist в `localStorage` | Минимальный стор, переживает перезагрузку |
| Контент | Локальные TS/JSON файлы в `/content` | CMS не нужна, правки — через PR, версионируются в git |
| Изображения | Резолвер ассетов: схематический SVG в MVP → `next/image` + AVIF/WebP позже. См. `12-schematic-assets.md` | Фотографий нет; замена не должна трогать компоненты |
| Формы | React Hook Form + Zod | Валидация гравировки и email одной схемой |
| Анимации | CSS transitions + `framer-motion` точечно | Только кросс-фейд превью и появление панели |
| Экспорт списка кадров | Клиентская генерация markdown/CSV + `@media print` | Мастеру нужен печатный список, а не веб-страница |
| Аналитика | **Не подключается.** Вынесена в `10-deferred.md` | Зритель один — измерять нечего |
| Деплой | Vercel | Нулевая настройка, preview-деплой на каждый PR — удобно для ревью |
| Шрифты | `next/font`, self-hosted | Без обращений к Google Fonts |

## Ключевые принципы реализации

**Никаких магических чисел в коде.** Цены, размеры, доступность, тексты — всё в `/content`. Разработчик не должен лезть в компоненты, чтобы поменять цену или убрать цвет из наличия.

**Цены — только в целых минорных единицах (гроши).** `35900`, а не `359.00`. Никакой плавающей точки в расчётах.

**Конфигурация валидируется одной Zod-схемой** и в URL-парсере, и в корзине, и в API-ручке. Одно определение истины.

**Конструктор — клиентский компонент, лендинг — статический.** Лендинг рендерится в SSG и отдаётся с CDN; конструктор гидрируется отдельно и не тянет свой вес в первую загрузку.

**Никакого бэкенда вообще.** Всё статическое, экспорт списка генерируется в браузере. Появление первой API route — сигнал, что скоуп поехал.

## Требования к производительности

- LCP ≤ 2,0 с на 4G (лендинг статический — это достижимо)
- CLS ≤ 0,05 — превью конструктора имеет фиксированный `aspect-ratio`, макет не прыгает
- INP ≤ 200 мс на переключении цвета
- JS-бандл конструктора ≤ 150 KB gzip
- В MVP сетевых запросов за изображениями нет вообще: и превью, и слоты — SVG/разметка
- Prefetch превью включается вместе с переходом на фотографии

## Что будет позже: Payload CMS 3

Решение по платформе для фазы продаж принято — **Payload 3** (`15-platform-comparison.md`). Он ставится **в это же приложение**, а не заменяет его: админка и бэкенд появляются в папке `app`, отдельного сервиса и Redis не требуется.

Что это означает для текущей разработки:

| | |
|---|---|
| Менять сейчас | **Ничего**, кроме одного файла-фасада `lib/data.ts` (задача T-025) |
| Что переедет | `content/*` → коллекции и глобалы Payload |
| Что НЕ переедет и не изменится | `lib/pricing.ts`, `lib/availability.ts`, `lib/config-schema.ts`, `lib/config-url.ts`, весь конфигуратор и все схемы |
| Что добавится | Коллекции заказов, остатка кожи, очереди производства; Stripe с BLIK/P24 |
| Когда | Только при решении открывать продажи |

⚠️ **Не создавать коллекции, базу или зависимости Payload заранее.** Пустая инфраструктура «на будущее» — это стоимость сегодня ради выгоды через полгода.

## Что осознанно не используем

| Не берём | Почему |
|---|---|
| Redux / сложный стейт-менеджер | Конфигурация — это 8 полей в URL |
| CMS (Sanity, Contentful, Strapi) | Контент меняется раз в месяц, git справляется |
| База данных | Нечего хранить: заказов нет, email уходит в Resend |
| Three.js / 3D-превью | Превью — SVG-чертёж, позже фото. См. `12-schematic-assets.md` |
| Библиотеки UI-китов (MUI, Chakra) | Бренд требует собственной эстетики, кит будет сопротивляться |
| Docker, CI-пайплайны | Vercel деплоит из git |
| Payload, Medusa, любая CMS или коммерческая платформа | Фаза 4, не раньше. См. выше |
| Асинхронные обёртки над `lib/*` «на будущее» | Усложняют все компоненты ради выгоды, которая наступит через полгода |
